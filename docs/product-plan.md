# Product plan · Craft Migration Service

Аудитория: пользователи Craftum community — уход с подписки на конструктор, сайт на своём домене и хостинге.

## Модель продукта

**Migration-as-a-service + deployable admin**, не SaaS-конструктор.

```
Реклама → 1 страница бесплатно → открыть копию → заявка
Оператор: завести Клиента (имя, домен) → миграция (агент/скилл + crawl)
         → на карточке клиента: скачать ZIP + инструкция
```

Публичная воронка **не** выдаёт боевой архив. Источник правды поставки — **карточка клиента** в админке Craft.

## Рекомендованный контур (фундамент)

Два разных продукта в одном сервисе. Их нельзя смешивать в одном job.

### 1. Главная — только проба

Пользователь вставляет URL Craftum. Снимаем **ровно одну страницу** (ту, что в URL, обычно главная). Сразу открываем **готовую копию** (`/preview/{jobId}/`), не анкету и не «ждите ZIP».

Это реклама возможности: «сайт как был». Не полный сайт, не админка клиента, не архив.

Ссылки меню на **неимпортированные** страницы в демо оставляем на **живой Craftum** (абсолютный исходный URL). Иначе пункт «О нас» ведёт в 404 нашего preview. Пользователь видит одну страницу 1:1 и понимает, что остальное — после оплаты.

### 2. Заявка — не кнопка «скачать»

После preview: Basic / Pro, контакты, **будущий домен** (даже если ещё не куплен), почта для форм, комментарий. Это заказ оператору, не самообслуживание экспорта.

Оплата (пока вручную, потом ЮKassa) только фиксирует, что можно делать работу. **Пересборку сайта кнопка «Оплачено» не запускает.**

### 3. Клиент в админке Craft — папка поставки

Вы **заводите клиента**: имя, целевой домен, тариф, контакты. Заявку с главной можно превратить в клиента одной кнопкой, но карточку создаёте вы.

На карточке после работы:

- скачать **архив**
- скачать **инструкцию** (`INSTRUKTSIYA.txt`, тот же файл, что в ZIP)
- preview job, статус валидатора

Не на `/demo/{id}` у посетителя и не «ссылка после оплаты» как основной канал. Клиент получает файл от вас; при желании позже можно выслать ту же ссылку с карточки.

### 3b. Как мигрировать: не автомат, связка админка + агент

Каждый Craftum-сайт свой (DOM, CDN, меню, коллекции). Кнопка «съесть весь сайт и сразу ZIP» — не обещание продукта.

| Слой | Роль |
|------|------|
| Админка | учёт: клиент, домен, имя, URL источника, какой job привязан. Поле URL + выбор клиента из списка. Можно «поставить crawl в очередь» как старт. |
| Агент оператора (скилл в Cursor, как сейчас) | индивидуальная миграция: снять страницы, поправить пути, шаблон пакета (ZIP + README + `.env.example` с доменом/именем), прогнать валидатор. Пишет **в этого клиента**, не в случайную папку. |
| Валидатор | до кнопки «Скачать ZIP»: нет `/preview/{uuid}/` в HTML/CSS; CSS и ключевые картинки 200; список страниц = page-model; внутренние ссылки Pro локальные. Красный — архив не отдаём. |
| Шаблон пакета | один и тот же каркас export (`public/`, `data/`, `server.mjs`, README). Агент/сборка только подставляют домен и имя клиента. |

**Как советуем работать:** в админке создали клиента и вписали URL → агент по скиллу ведёт миграцию на этого клиента → валидатор зелёный → ZIP на карточке.

Поле URL + список клиентов **нужно** (иначе нет реестра и некуда класть архив). Одного поля **мало** как «умной миграции». Playwright-crawl — черновик, не сдача.

Agent API **на хостинге клиента** (Phase 14) — другое: правки уже выложенного сайта. Не путать со скиллом оператора при миграции.

Полигон `demo.nordic-builder.ru` — ваш стенд, не публичное демо посетителя.

### 4. Что уезжает клиенту

Один архив, три способа жить:

| Режим | Как | Формы | Админка |
|-------|-----|--------|---------|
| Локально посмотреть | из папки `public/` поднять простой static server (`npx serve public`) | нет | нет |
| Локально править | `node server.mjs` | можно выключить в `.env` | `/admin` |
| Боевой хостинг | nginx → Node | email / позже TG | `/admin` |

`file://` не обещаем: пути `/assets/…` и `/about/` требуют HTTP с корня сайта.

В ZIP всегда: `public/`, `data/source/`, `content.json`, `page-model.json`, `admin.html`, `server.mjs`, `patch.cjs`, **README с двумя сценариями** (открыть сайт / запустить редактор).

### 5. Админка на хостинге клиента

Не путать с `/admin` сервиса Craft.

**Страницы.** Клиент видит полный список выгруженных URL: путь (`/`, `/about/`), title, «открыть на сайте». Basic — одна строка. Pro — все снятые страницы. Пути из `page-model`, не угадывание из меню.

**Меню.** Отдельный экран: пункты шапки/подвала (подпись + href), не прятать это в куче полей секций. Правка href применяется ко **всем страницам пакета** (шапка одна и та же в HTML). Внутренние ссылки — на пути из списка страниц; внешние — как есть. Добавить/убрать пункт меню в MVP только если якорь в DOM однозначный; иначе оператор через HTML-блок / скилл.

**Привычка Крафтума, не WordPress.** Клиент открывает редактор и видит **свой сайт**, как в конструкторе: полотно страницы, слева/сверху список страниц и путей, клик по тексту/фото/пункту меню → правка. Не таблица полей как админка WordPress. Админка сервиса Craft (`/admin` у вас) может оставаться WP-style — это другой пользователь.

Сценарий как в Craftum:

1. Выбрал страницу из списка (путь виден: `/`, `/contacts/`).
2. Смотрит живой HTML (как опубликованная страница).
3. Кликает блок — подсветка, справа подпись/ссылка/картинка.
4. Меню правит на самой шапке (клик по пункту) или коротким списком «Меню», те же href на всех страницах.
5. Сохранить черновик → Опубликовать — страница на сайте меняется, вёрстка та же.

Puck (или тот же паттерн оверлея) — инструмент клика по DOM, не новый конструктор «собрать сайт заново». Не копируем бренд/хром Craftum, копируем **жест**: вижу сайт → тыкаю → меняю.

Порядок: список страниц + меню + publish на живом preview, затем полноценный оверлей. Запасной список полей — для отладки оператора, не главный экран клиента.

### Почему не «оплатил → сам полный crawl → ZIP на /demo»

- Демо и Pro — разный объём и разные правила ссылок.
- Домен и почта форм должны попасть в пакет до zip, иначе снова `YOUR-DOMAIN.RU` и preview-пути.
- Вы сами смотрите результат (полигон ua9043 это показал: без прохода оператора стили/фото легко уезжают криво).
- Посетитель не должен крутить Playwright на весь сайт бесплатно.

ЮKassa и Agent API по-прежнему после живого контура.

## Воронка

| Шаг | Кто | Действие | Цена |
|-----|-----|----------|------|
| 1 | посетитель | URL → 1 страница → открыть копию | бесплатно |
| 2 | посетитель | заявка: тариф, домен, контакты | 0 |
| 3 | вы | оплата отмечена | разово |
| 4 | вы | клиент в админке + миграция (скилл/crawl) + валидатор | в цене тарифа |
| 5 | вы | с карточки клиента: ZIP + инструкция | в тарифе |
| 6 | клиент | static локально или Node на хостинге | — |

**Техподдержка не входит в базовую цену** — отдельно по договорённости.

## После разработки · замкнуть контур 📋

Когда код стабилен:

1. Прогнать миграцию боевого Craftum-сайта (не только e2e).
2. Развернуть пакет на **демо-домене оператора** (свой хостинг / VPS / Beget).
3. Пройти путь **глазами клиента**: сайт, формы, редактор `/admin`, публикация, смена текстов.
4. Только после этого — ЮKassa и реклама воронки.

## После контура · Agent API 📋

На хостинге клиента, не у нас: агент (оператора или клиента) по ключу владельца дорабатывает сайт через слоты HTML + `content.json` + publish. Сайт остаётся legacy HTML. Поддержка «по запросу» руками — тот же слой, без агента.

---

Техподдержка не входит в базовую цену — отдельно по договорённости.

## Что получает клиент после оплаты

```
export.zip
├── public/            # HTML + assets
├── data/source/       # HTML до правок клиента
├── data/content.json
├── data/page-model.json
├── admin.html         # редактор страниц
├── patch.cjs
├── server.mjs         # сайт + POST /api/form + /admin
└── INSTRUKTSIYA.txt
```

## Формы

Настройки Craftum (почта конструктора, их CRM) **не используем**. Submit перехватываем, заявка всегда в **админку как CRM**.

Пока:

- клиентский `/admin` — входящие заявки (`data/leads.jsonl`)
- ваша админка Craft — CRM клиентов/заказов (карточки, ZIP)

Email / Telegram / Sheets — опционально поверх инбокса, не условие приёма заявки. Визуальный редактор «как в Craftum» — отдельно, позже.

## HTML-блоки и AI

- Владелец вставляет секции HTML + `<style>` + `<script>`
- AI (OpenAI): prompt → HTML + style tag → preview → вставка в slot
- API key хранится на сервере клиента, не в браузере

## Хостинг клиента

Целевой: Beget, Timeweb, VPS с Node.js.  
Требование: возможность запустить Node-приложение (admin + api + publish).

## Монетизация

1. **Разовая миграция** — основной доход
2. **Установка под ключ** — доп. услуга
3. **Care / поддержка** — опционально, отдельно (не в базе)
4. **Agent API / доработки сайта** — после миграции, на хостинге клиента
