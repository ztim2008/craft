## Публикация блоков для обычных пользователей

**Записано:** 2026-09-02

**Сейчас:** publish доступен только администратору каталога — ключ `CRAFTUM_BLOCKS_PUBLISH_KEY` (админка → popup расширения → «↑ В каталог»).

**Идея:** дать **обычным пользователям** расширения возможность добавлять свои блоки в каталог — без админского ключа и без доступа к `/admin/craftum-blocks`.

**Зачем:** рост каталога за счёт сообщества; авторы делятся блоками, другие вставляют.

**Что продумать позже:**

- Аутентификация автора (аккаунт Craft / OAuth / invite-код)
- «Мои блоки» vs «Каталог сообщества» — отдельные списки или модерация перед публикацией
- Лимиты (блоков на пользователя, rate limit publish)
- Модерация / report / удаление
- Связка с монетизацией ([monetization.md](./monetization.md)) — платные наборы vs бесплатный community

**Не путать с:** клоном блока в админке под новым id (уже работает для автора каталога).

## Резервная доставка заявок с форм Craftum (через расширение)

**Записано:** 2026-09-02

**Контекст:** пользователи на **живом Craftum** (не мигратор) жалуются — заявки с форм не доходят на почту и в Telegram. Это штатный бэкенд Craftum (`POST /user-website-api/form/` на опубликованном сайте). Мы это **не контролируем**.

**Ограничение расширения сейчас:** content script только на `craftum.com` (редактор). Посетитель сайта **без** расширения — а заявки шлют именно посетители. Одним расширением на машине автора проблему **не перехватить**.

### Реалистичный выход: расширение как «мастер настройки» + скрипт на сайте

Расширение в редакторе Craftum помогает **один раз** включить резервный канал на опубликованном сайте:

1. В popup/FAB: «Резервная доставка заявок».
2. Автор указывает Telegram (bot token + chat id) и/или email.
3. Расширение (или страница craft.nordic-builder.ru) генерирует **короткий JS-сниппет** + site-token.
4. Автор вставляет сниппет в Craftum: **Настройки сайта → HTML → Пользовательский HTML** (как WebJack).
5. Сниппет на **опубликованном** сайте (`*.craftum.io` / свой домен):
   - перехватывает успешный `fetch` на `/user-website-api/form/` (или `submit` формы);
   - дублирует payload на `craft.nordic-builder.ru/api/craftum-forms/relay` (или аналог);
   - наш сервер шлёт Telegram / SMTP **независимо** от Craftum.

**Плюсы:** работает для всех посетителей; не нужен Craftum fix; ложится в линию Craftum Blocks (расширение + наш API).

**Минусы:** ручной шаг HTML; дублирование заявок если Craftum починится; нужен backend + rate limit + согласие 152-ФЗ; custom HTML может конфликтовать с капчей.

### Дополнительно в расширении (диагностика, без relay)

| Функция | Где | Зачем |
|---------|-----|--------|
| **Проверка формы** | Редактор / превью | Открыть опубликованный URL, отправить тест, показать status POST и тело ответа |
| **Чеклист Telegram** | Popup | «Переподключите @Craftum_bot» + ссылка на help Craftum |
| **Health VPN** | `craftum.com/app` | Если `api-v2.craftum.com` / WebSocket падает — toast: split-tunnel, отключить VPN |

**VPN починить расширением нельзя** (QRATOR, маршрутизация, WebSocket) — только подсказки.

### Не делать

- Проксировать весь Craftum API через наш сервер (cookies, ToS, латентность).
- Content script на все домены без явного согласия автора.
- Подменять штатную отправку формы — только **mirror после успеха** или parallel notify.

### Связь с продуктом

- Монетизация: бесплатно N заявок/мес, дальше тариф (см. monetization.md).
- Альтернатива WebJack для «просто Telegram + email» без тяжёлой интеграции.
